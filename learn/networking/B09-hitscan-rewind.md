# B09：Hitscan 服务端命中回溯

本切片由 AI 协作实现，在 UE5.6.1 完整编译与 Listen Server +1 Client PIE 中验证。不是完整竞技游戏反作弊方案。

## 一枪的数据流

1. 拥有客户端用相机 TraceAim 得到目标点，提交当前武器、递增 ShotId、同步服务器时间减半个 Ping。
2. CombatComponent 服务器 RPC 检查比赛阶段、序号、时间窗口、武器归属、弹药、换弹、射速、距离、瞄准方向和枪口遮挡。
3. 服务器每秒最多约30次保存七个骨骼的世界 Transform，保留约1秒，硬上限34帧。不可见角色也刷新骨骼。
4. Hitscan 在两个历史帧之间插值，将射线转换到各盒子的局部空间求交。选择当前世界遮挡之前最近的历史命中。
5. 服务器结算身体20/头部40伤害，扣一发弹药；属性复制和 Multicast 更新其他端。

实现入口：`Source/Blaster/BlasterComponent/CombatComponent.cpp` 的 ServerFire 与 `LagCompensationComponent.cpp` 的 SampleFrame/ConfirmHit。

## 实际验证

| 场景 | 结果 |
| --- | --- |
| 当前身体命中 | 100→80 |
| 目标横移300cm后请求旧帧 | 80→60，目标当前Transform完全不变 |
| 当前时间沿旧方向开火 | 未伤害，正常扣弹 |
| 爆头 | 60→20 |
| 未来1s、过去2s、NaN、空武器、重放或非正序号 | 发射计数与弹药不变 |
| 非拥有客户端调用其他角色RPC | 忽略；相同服务器调用能成功 |
| Net PktLag=100，客户端测得约153ms | 两次真实输入命中，100→60 |

初次测试在栏杆后误判为命中失败。实际 Visibility Trace 确认枪口前47cm存在栏杆，换到通畅位置后命中。排查网络前先检查真实射线。

## 取舍与后续

- 回溯只计算数据，不临时移动Actor、不切换碰撞，因此不会污染并发射击或物理世界。
- 时间容忍上限为 `min(1s, RTT+0.2s)`；客户端可选择容忍范围内的时间，存在公平性取舍，不能称为防作弊完成。
- 七个粗略身体盒不是精确PhysicsAsset；头部/身体盒重叠与边缘命中需要美术校准。
- 历史数量有界，内存随玩家数线性增长。单枪遍历玩家及七个盒；实际CPU/内存尚未性能采样，不提供虚构毫秒指标。
- 当前枪口与世界遮挡不回溯；移动门、平台与射手快速移动时存在误差。
- 新出生角色历史不足时不会补造历史。

### Shotgun SSR 设计（未实现）

服务器接受一次射击序号和种子，产生全部pellet方向；全部pellet使用同一历史时刻。按Actor聚合身体/头部命中后一次结算，整枪只扣一发。验收包括重复请求、同枪不同历史时间、墙体遮挡、多个目标、聚合伤害上限。

### Projectile SSR 设计（未实现）

客户端预测弹道只作表现；服务器验证初始位置/速度/射击时间，按固定步长扫掠球体，并采样各飞行时刻的目标历史。限制最大模拟时长和步数。服务器命中与本地预测需用ShotId去重并校正；不能同时保留当前权威Projectile伤害和回溯伤害。验收覆盖高速穿透、延迟超过历史、预测消失、重复命中、移动世界遮挡和爆炸半径。
