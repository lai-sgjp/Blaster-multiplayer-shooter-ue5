# 作品集表述与复盘

以下是课程项目的AI协作成果，不能直接包装成个人独立设计。求职前应能现场解释、修改和复现；未验证功能不写成已上线。

## 三条简历候选

1. 基于UE5.6多人射击课程，在AI协作下完成C++服务器权威战斗闭环，覆盖三类命中模型、弹药、双武器、淘汰重生与比赛循环，并进行双端PIE主路径和失败路径验证。
2. 实现Hitscan服务端历史命中检测，使用约1秒骨骼盒历史、插值与请求序号/时间/归属校验，验证历史移动目标命中、重复请求拒绝及约153ms实测Ping下射击。
3. 整理RPC到Replication/OnRep/Multicast及HUD的数据流与验证矩阵，记录当前世界遮挡、粗命中盒、DX12稳定性和未完成公网/打包验证等边界。

## 十个代码复盘问题

1. 为什么非拥有客户端不能调用另一角色Combat的Server RPC？进一步指出服务器仍需验证什么。
2. ShotId去重与NextServerFireTime各阻止什么？为什么客户端FireTimer不能证明射速合法？
3. TraceAim从相机发射，实际子弹从枪口发射，如何处理近墙和背后目标？
4. Projectile、Hitscan、Shotgun分别在哪一刻、哪一端结算伤害？pellet为什么先聚合？
5. Health、bEliminated、Score分别属于哪个对象？Pawn替换后为什么分数不丢？
6. 换弹计时期间死亡会怎样？为什么FinishReload还要重新检查状态？
7. 主副武器的Owner、Attachment、隐藏、碰撞和寿命如何改变？只改可见性为什么不够？
8. SSR为什么不需要移动真实角色？历史插值、粗盒与当前世界遮挡分别有哪些误差？
9. 为什么客户端时刻需要同步服务器时间？RTT/2估计在哪些网络条件下不准确？
10. 证明比赛完成需要哪些证据？为什么同进程PIE不能证明Steam公网、专用服务器或打包稳定？

回答时先打开对应源码，画出输入→服务器验证→权威改变→网络同步→表现的链路，再说明实测与未验证项。不要求先答题才能继续开发。
